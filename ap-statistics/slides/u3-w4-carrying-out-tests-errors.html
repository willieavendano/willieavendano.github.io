Where We Are

You can compute a p-value. Now what?

Last week ended with a number like “p-value ≈ 0.038” and nothing else. A p-value by itself isn't a conclusion — it has to be compared against a threshold and translated into a sentence a reader can act on.

Carrying Out the Test

P-value vs α

One comparison decides everything.

Keep this divider's message simple on purpose — the decision rule genuinely is a single comparison. The complexity that follows is entirely about wording the conclusion correctly, not the math.

Carrying Out · 1 of 4

Compare the p-value to the significance level

The rule

α (“alpha”), the significance level, is a threshold decided before collecting data — almost always α = 0.05 unless a problem states otherwise.

  • p-value < α → reject H₀
  • p-value ≥ α → fail to reject H₀

Small p-value = the data would be surprising if H₀ were true = evidence against H₀.

Carrying Out · 2 of 4

Two words that don't exist in this classroom

Never write
  • “We accept H₀.” — failing to reject is not the same as proving it true.
  • “This proves …” — statistics never proves anything, it weighs evidence.
Always write
  • “We have convincing statistical evidence that …”
  • “We do not have convincing statistical evidence that …”

Every conclusion this year, in every unit, uses this exact vocabulary. No exceptions.

This is the single most heavily graded piece of language in the entire course. AP readers are specifically trained to withhold the conclusion point for "accept H0" or "prove." Make students write the full sentence, in context, every single time — never let "reject H0" stand alone as a final answer.

Carrying Out · 3 of 4

The conclusion sentence, template

Fill in every blank, every time

“Since the p-value (___) is less than / not less than α (___), we reject / fail to reject H₀. We have / do not have convincing statistical evidence that [Ha's claim, in context].”

The context clause at the end is not optional — a bare “we reject H₀” earns partial credit at best.

Carrying Out · 4 of 4

Worked example, start to finish

Revisit the factory: H₀: p = 0.04, Hₕ: p > 0.04, z ≈ 1.77, p-value ≈ 0.038, using α = 0.05.

StepWhat you write
K(from last week) n = 300, p̂ = 0.06, conditions checked ✓
DH₀: p = 0.04, Hₕ: p > 0.04, p = true defect rate
Eone-sample z-test; α = 0.05
Az ≈ 1.77, p-value ≈ 0.038. Since 0.038 < 0.05, we reject H₀. We have convincing statistical evidence that the true defect rate is greater than 4%.
This is the exact same problem from last week's deck, now carried all the way to a conclusion — a deliberate callback so students see the full arc: hypotheses → statistic → p-value → decision → conclusion, in one continuous KDEA table. Point out the conclusion names the direction (greater than 4%), matching Hₐ exactly — a conclusion that doesn't match the stated alternative is wrong even if the reject/fail-to-reject call was right.

A Second Look · Fail to Reject

What it looks like when the evidence isn't there

A school claims p₀ = 0.75 of students pass the state exam. A random sample of n = 120 students finds 85 pass. Test at α = 0.05, two-sided.

StepWhat you write
Kp̂ = 85/120 ≈ 0.708; conditions: Random ✓, 10% ✓, np₀ = 90 ≥ 10, n(1−p₀) = 30 ≥ 10 ✓
DH₀: p = 0.75, Hₕ: p ≠ 0.75
Eone-sample z-test, two-sided
Az = (0.708−0.75)/√(0.75 × 0.25/120) ≈ −1.06. One-tail area ≈ 0.145, doubled ≈ 0.289. Since 0.289 ≥ 0.05, we fail to reject H₀. We do not have convincing statistical evidence that the true pass rate differs from 75%.
Check: 0.75×0.25 = 0.1875, /120 ≈ 0.001563, √ ≈ 0.0395, z ≈ −1.06. Normalcdf gives about 0.1446 in one tail, doubled ≈ 0.289. This example deliberately shows the OTHER outcome — students who only ever see "reject" examples wrongly start to think every test rejects. Emphasize "fail to reject" is not a failure of the analysis; it's information too.

When the Decision Is Wrong

Every test can make a mistake. Which one matters more?

Type I and Type II errors.

Frame this divider around the idea that NO test is ever 100% certain — every decision rule has some chance of being wrong in one of two specific ways. The rest of the week is about naming those ways and reasoning about their real-world costs, which is exactly the FRQ skill tested here.

Errors · 1 of 4

Type I error: a false alarm

Definition

Rejecting H₀ when H₀ is actually true. You conclude there's an effect or difference — there isn't one.

The probability of a Type I error is exactly α — that's the whole reason we set a significance level before starting.

In context

A medical test says a patient has a disease they don't actually have — an unnecessary scare and unnecessary follow-up treatment.

Errors · 2 of 4

Type II error: a missed signal

Definition

Failing to reject H₀ when H₀ is actually false. There really is an effect or difference — the test misses it.

The probability of a Type II error is called β (“beta”) — harder to compute than α, but conceptually the mirror image.

In context

A medical test says a patient is disease-free when they actually have the disease — a dangerously missed diagnosis.

Errors · 3 of 4

The full picture, side by side

DecisionH₀ is actually trueH₀ is actually false
Reject H₀Type I error (probability α)Correct decision
Fail to reject H₀Correct decisionType II error (probability β)

Only two ways to be right, only two ways to be wrong. This table is the whole idea.

Have students copy this table verbatim — it's the single most reliable way to keep Type I and Type II straight under test pressure. Cross-reference: "Type I" pairs with "reject when true"; "Type II" pairs with "fail to reject when false." Some students find it easier to remember Type I as the error you can control directly (you set α), Type II as the one you mostly influence indirectly (through sample size and effect size).

Errors · 4 of 4

Which error is worse? It depends on the stakes.

Worked scenario — airport security screening

H₀: a passenger's bag contains no prohibited item. Hₕ: it does.

  • Type I (false alarm): flagging a safe bag — costs time, inconvenience.
  • Type II (missed signal): clearing a bag that actually has a prohibited item — a serious safety failure.

Here, Type II is far more costly — which is why security screening is deliberately tuned toward catching more false alarms.

This is the exact skill AP FRQs test: given a scenario, identify both errors in context AND argue which is worse. There's rarely a single "correct" answer — the grading rewards a clear, reasoned argument tied to the specific consequences described. Contrast this scenario with the earlier medical-test example, where the "worse" error depends heavily on the specific disease and treatment.

One More Idea

Power: catching a real effect when it's there

Power = 1 − β

The probability of correctly rejecting a false H₀ — correctly detecting an effect that's really there.

n ↑
Larger sample
increases power
α ↑
Higher significance level
increases power (but raises Type I risk)
Δ ↑
Bigger true effect
increases power — easier to detect a big difference

Real power calculations lean on software — R's pwr package, Python's statsmodels — rather than hand computation.

Keep this brief — power is a CED topic but not the star of this week. The key intuition: power and Type II error are two sides of the same coin (power = 1 − β), and the three levers that raise power are the same three that appear on almost every "how would you improve this study" FRQ prompt.

Practice · Turn & Talk · 10 minutes

Name the errors, argue the stakes

With your partner

A pharmaceutical company tests H₀: p = 0.01 (the drug's serious side-effect rate is 1%, the same as the current standard drug) against Hₕ: p > 0.01 before approving a new drug for sale.

  1. Describe the Type I error in context.
  2. Describe the Type II error in context.
  3. Which error is worse here? Justify your answer.
Type I: concluding the new drug has a higher side-effect rate when it actually doesn't — the drug gets unfairly blocked from the market. Type II: concluding the side-effect rate is fine when it's actually higher — an unsafe drug reaches patients. Most groups will (correctly) argue Type II is worse here given patient safety, but accept well-reasoned arguments either direction — the argument quality is what's graded, not a single "correct" side.

Common Test Traps

Four ways this goes wrong on paper

✕
“Accept H₀”
Never write this. “Fail to reject” is the only acceptable phrase.
✕
No context
“We reject H₀” alone earns partial credit — the claim must be restated in context.
I / II
Mixing up error types
Use the table: reject + H₀ true = Type I. Fail to reject + H₀ false = Type II.
p
Using p̂ for Large Counts
In a test, Large Counts uses p₀ — not p̂.
