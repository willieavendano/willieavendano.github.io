Concept

Deck The Data You Generate not built yet

Every model starts as a table someone had to design. Rows are observations, columns are variables — and choosing them badly is a decision you cannot undo later.

Deck Lookup & Aggregate not built yet

Two moves do most of the work in every model this year: fetch a fact from a reference table (VLOOKUP), and summarise many rows into one number (SUMIF/AVERAGEIF).

Practice

Lookup & Aggregate Practice — csm-p1-tracker-practice.xlsx

  1. Given a 15-food reference table, return the calories for a named food — then break it on purpose by misspelling the name, and fix it.
  2. Total calories for a single day using SUMIF; then average across days with AVERAGEIF.
  3. Add a food to the reference table and confirm every downstream number updates without editing a formula.
  4. Find the deliberately planted hard-coded cell and replace it with a formula.

Explore

Macro Explorer not built yet

Log foods and watch macros recompute live; drag a portion slider to see how one change ripples through daily totals. Students meet the behaviour before they build the mechanism.

Build — what you hand in

Food & Macro Tracker (Thu Oct 15)

A working tracker over ≥14 days of your own logged data: reference table, daily log with lookups, aggregated dashboard, and one honest chart answering a question you chose.

Stretch (optional). Add a second reference table (cost per serving) and answer a second question: what does a day of your eating cost?

Rubric

Every cornerstone is scored on the same five criteria, so you always know what "good" means before you start.

Criterion4 Advanced3 Proficient2 Developing1 Beginning
Model CorrectnessDoes it compute the right answer, for the right reason? Every output is correct and stays correct when inputs change. Edge cases (zero, negative, extreme values) behave sensibly or are explicitly blocked. Outputs are correct for reasonable inputs. The model holds together when assumptions are changed. Outputs are correct for the one case that was tested. Changing an input breaks something or produces a silently wrong number. Outputs are wrong, missing, or cannot be recomputed from the inputs shown.
Formula HonestyIs the arithmetic real, or is it typed in? Nothing is hard-coded that should be computed. Every assumption is a labelled input cell that the formulas reference. Precision claimed matches precision earned. Formulas do the work; inputs live in their own cells. Any constant is a genuine constant and is labelled. Some results are typed in rather than computed, or magic numbers are buried inside formulas. Rounding is applied inconsistently. Key results are typed in. Changing an input does not change the answer — the model is a picture of a model.
Data StructureCould a stranger navigate this file? Inputs, calculations, and outputs are cleanly separated. Tabs, headers, and named ranges make intent obvious without explanation. Consistent formatting throughout. Logical tab and column organisation with clear headers. A reader can find the inputs and follow the calculation. Organisation is inconsistent — inputs mixed with results, unlabelled columns, stray working cells left in place. No discernible structure. The reader cannot tell what is an input, what is a result, or what is scratch.
CommunicationDoes the chart and the write-up tell the truth clearly? Charts are chosen for the question being answered, axes are labelled and honest, and the write-up states the conclusion, the assumptions behind it, and what would change it. Charts are appropriate and labelled. The write-up states the conclusion and the main assumptions. Charts exist but mislead or decorate — truncated axes, wrong chart type, missing labels. The write-up describes what was built rather than what it means. No chart, or a chart that cannot be read. No stated conclusion.

Implements the stretch task correctly. Stretch attempted but incomplete or not integrated with the main model. Not attempted (no penalty — this criterion is optional).
